# CR-02 变更裁定：候补队列二期增量

| 项 | 内容 |
|---|---|
| 变更请求 | CR-02 候补队列（承接 CR-01 / CRQ-10） |
| 来源 | 客户坚持实际交付 `00-customer-brief.md` §6 的候补诉求 |
| 决策依据 | `cr01-impact.md`（方案 B：2.5 人日 / ¥1,475）、`ccb-cr01.md`（原延期理由）、一期收尾数据 |
| 裁定日期 | 2026-10-24（一期验收后） |
| 裁定 | **有条件批准**：作为二期增量交付，不改一期基线 |

## 1 范围

**做**：

- 学生登记候补（`waitlist join`），同一人同一设备重叠时段只允许 1 条 `waiting`；
- 候补名单（`waitlist list`）：admin 用 `--all` 看全部，student 只看本人，director 拒绝；
- 审计事件 `waitlist_join`；
- 候补不占用时段，`request approve` 的冲突判定与有无候补记录无关。

**不做**：通知、自动递补、取消候补、候补转正式申请。

## 2 对一期的影响

| 项 | 结果 |
|---|---|
| 范围基线 | 一期 16 条不变；CRQ-10 在二期单独记录 |
| 进度基线 | 一期 18.75 天不变 |
| 成本基线 | 一期 BAC 15,800 不变 |
| EVM | EV 15,800、AC 17,974.90、CPI 0.879、SPI 1.000 不变 |
| 验收结论 | 16/16 不变 |

二期单独记 **2.5 人日 / ¥1,475**，不占用一期应急储备与管理储备，不进入一期 CPI/SPI。排期：2026-11-30 08:00 → 2026-12-02 12:00，2.5 个工作日；关键路径 6.1→6.2→6.3→6.4→6.5。

## 3 附加条件

1. QA 按 AC1–AC4 出具可复现证据：退出码、`waiting` 条数、`waitlist_join` 审计、approve 冲突判定与候补无关。
2. 二期文档单独标注“CR-02 二期”，一期基线文件只做引用、不回改。
3. 二期实际超过 3 人日或 ¥1,800，立即停工回报 CCB。
4. CR-01 标记为“由 CR-02 承接”，不重复实施。

## 4 验收口径（AC1–AC4）

| AC | 判定 |
|---|---|
| AC1 | `waitlist join` 成功：退出码 0，库中 1 条 `waiting`，审计 `waitlist_join` 1 条 |
| AC2 | 同人同设备重叠时段重复登记：退出码 1，库无新增 |
| AC3 | 候补不占位：同一 pending 申请在“有 waiting”与“无 waiting”两个库上 approve，结果完全一致 |
| AC4 | 可见性：admin `--all` 见全部，student 见本人，director 退出码 3 |

## 5 结论

CR-01 由 CR-02 承接，按上述边界实施；一期基线、EVM 与验收结论保持冻结。
