## 2 干系人管理策略

| 干系人 | 利益相关度 | 影响程度 | 管理策略（具体动作） |
|---|---|---|---|
| 学生 / 教师 | 高 | 低 | 需求以客户档案为准，不自造需求；每包交付后提供可试用的演示脚本，收集 1 轮反馈 |
| 实验室管理员 | 高 | 高 | 每周状态报告 + 每包演示；审批与逾期口径由其确认；CR-01 变更必须先取得其书面意见 |
| 实验中心主任 | 中 | 高 | 里程碑汇报（5 个工作包各 1 次）；只看进度、成本、NPV 与冲突阻止结果，不进入实现细节 |
| 实验中心（单位） | 中 | 高 | 章程与验收结论走正式签署；预算上限 ¥19,700 与工期 20 天作为硬约束写入章程 |
| PM | 高 | 高 | 每工作日更新任务单与 EVM；偏差 >10% 时当天上报并发起纠偏 |
| BA | 高 | 中 | 契约文档先评审后交 Dev；需求变更只走 CCB，不口头改 |
| Dev | 高 | 中 | 按工作包领活，交付即附自测说明；不直接对接客户 |
| QA | 中 | 高 | 独立于 Dev 取证；未通过测试的工作包不计入 EV，不得进入下一包 |
| CCB | 中 | 高 | 每次评审 0.5 人日、¥250；裁定结果与影响分析归档，未批准不开发 |

## 3 启动会

**会议目的**：确认目标与成功标准、锁定范围基线、确认预算与工期口径、明确变更流程与分工。
**形式**：异步文档评审（多智能体团队无同步会议，本章记录议程、决议与待办）。

### 3.1 议程

| 序 | 议程项 | 主持 / 讲解 | 产出 |
|---|---|---|---|
| 1 | 与会角色与分工介绍 | PM | 角色职责确认 |
| 2 | 客户背景与问题回顾 | BA | 问题清单与业务目标 G1–G6 |
| 3 | 商业论证与章程评审 | BA / PM | 章程待签版 |
| 4 | 范围基线、工期与预算口径 | PM | 基线锁定结论 |
| 5 | 风险、变更流程与下一步计划 | PM / CCB | 待办清单 |

### 3.2 决议

| 编号 | 决议 |
|---|---|
| D1 | 范围基线锁定 CRQ-01~CRQ-09 与 NFR-01~NFR-07；CRQ-10（候补队列）不进入基线，作为变更候选 CR-01 提交 CCB 评审。 |
| D2 | 批准成本基线 ¥15,800 + 应急储备 ¥2,000 = ¥17,800；客户上限 ¥19,700，超出须 CCB 批准。 |
| D3 | 工期固定 20 个工作日，按 5 个工作包迭代交付，每包交付后演示。 |
| D4 | 所有变更统一走 CCB（0.5 人日 / 次），未批准不进入开发；变更影响必须写明对进度、成本、NPV 的影响。 |
| D5 | 验收以客户档案第 5 节的 6 条成功标准为准，凭演示与测试证据判定，不另加指标。 |

### 3.3 待办

| 事项 | 责任人 | 截止（相对工作日） |
|---|---|---|
| 章程与干系人文档送发起人评审签署 | PM | 第 2 个工作日 |
| 范围说明书与 WBS（含关键路径） | BA | 第 3 个工作日 |
| 进度与成本基线、EVM 口径确认 | PM | 第 4 个工作日 |
| 风险登记表、质量与测试计划 | BA / QA | 第 5 个工作日 |
| 演示数据集与演示脚本 | Dev | 第 8 个工作日 |

### 3.4 下次会议

第 5 个工作日，规划阶段结束评审（范围、进度、成本基线评审）；之后每工作日一份状态记录，每工作包结束一次演示。
