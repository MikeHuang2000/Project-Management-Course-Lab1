净现值分析（NPV）与挣值管理（EVM）分别服务于投资决策与项目执行监控两个不同阶段。NPV回答“**是否值得做**”，EVM回答“**做得怎么样**”。

---

### 净现值分析（NPV）

**核心逻辑**：今天的1元钱比未来的1元钱更值钱。NPV将项目全生命周期内的预期现金流入和流出，按反映资本成本与风险的折现率统一折算到当下，衡量项目在扣除资金成本后，究竟能创造多少绝对价值。

**计算公式**

\[
NPV = C_0 + \sum_{t=1}^{n} \frac{C_t}{(1+r)^t}
\]

其中 \(C_0\) 为期初净现金流（通常为负的投资支出），\(C_t\) 为第 \(t\) 期净现金流，\(r\) 为折现率（资本成本），\(n\) 为项目寿命期。

**决策规则（针对独立项目）**

| NPV 结果    | 含义                                           | 决策           |
| ----------- | ---------------------------------------------- | -------------- |
| **NPV > 0** | 投资报酬率 **大于** 资本成本，项目增加股东财富 | **采纳**       |
| **NPV = 0** | 投资报酬率 **等于** 资本成本，不改变股东财富   | 可采纳可不采纳 |
| **NPV < 0** | 投资报酬率 **小于** 资本成本，项目减损股东财富 | **放弃**       |

这一规则与“最大化股东财富”的财务目标直接一致。

**优点**

- **时间价值**：每一期现金流都按复利折现，符合金融基本原理。
- **绝对价值量**：直接给出“这个项目将为公司增加/减少多少元价值”的明确答案。
- **考虑资本成本与风险**：折现率本身就可以嵌入项目的风险水平。

**局限与适用边界**

- **折现率敏感且需要估算**：资本成本或贴现率的估计偏差会系统性地影响结论——偏低会接受本应拒绝的项目，偏高会拒绝本应接受的好项目。
- **不便于直接比较规模不同的项目**：NPV是绝对金额，一个大规模项目的NPV通常天然高于小规模项目，即便小项目的**回报率**更高。在资本受限、需要在不同规模项目之间取舍时，单看NPV可能不够。
- **互斥项目中的冲突**：当两个项目互斥且**规模或期限不同**时，NPV与内部收益率（IRR）可能给出相反的排序。NPV倾向于偏向规模大、总价值增量高的项目，IRR则可能偏向规模小但百分比回报更高的项目。理论上NPV的再投资假设（以资本成本再投资）更为合理，但在实务中IRR的百分比形式更易被直观理解。

### 挣值管理（EVM）

**核心逻辑**：仅看“花了多少钱”和“做了多少事”是不够的。EVM将范围、进度和成本统一到同一套货币尺度下，用“**实际完成的工作值多少钱**”（挣值）作为桥梁，同时诊断成本与进度两个维度。

**三个基本值**

| 指标               | 含义                                 | 计算                      |
| ------------------ | ------------------------------------ | ------------------------- |
| **PV（计划价值）** | 到某时点**计划**应完成工作的预算金额 | 计划工作量 × 预算单价     |
| **EV（挣值）**     | 到某时点**实际已完成**工作的预算金额 | 已完成工作量 × 预算单价   |
| **AC（实际成本）** | 到某时点**实际已发生**的总成本       | 实际完成工作量 × 实际单价 |

PV是“原计划值多少”，EV是“干出来的活按原计划值多少”，AC是“干这些活实际花了多少”。

**四个评价指标**

| 指标                    | 公式    | > 0 / > 1 的含义   | < 0 / < 1 的含义   |
| ----------------------- | ------- | ------------------ | ------------------ |
| **CV（成本偏差）**      | EV − AC | >0：**成本节约**   | <0：**成本超支**   |
| **SV（进度偏差）**      | EV − PV | >0：**进度提前**   | <0：**进度落后**   |
| **CPI（成本绩效指数）** | EV / AC | >1：成本效率**高** | <1：成本效率**低** |
| **SPI（进度绩效指数）** | EV / PV | >1：进度效率**高** | <1：进度效率**低** |

偏差指标给出“差了多少”（金额），指数指标给出“效率如何”（比例）。

**预测功能：从“现在怎么样”到“最终会怎样”**

EVM的价值不止于回顾偏差，更在于基于当前绩效**外推完工前景**。核心预测指标包括：

- **ETC（完工尚需估算）** ：从当前时点到完工还需要多少成本；
- **EAC（完工估算）** ：整个项目的最终总成本预计是多少；
- **VAC（完工偏差）** ：BAC（完工预算）减去EAC，预测最终是超支还是节约。

EAC的公式选择取决于对偏差性质的判断。若认为当前成本效率**将延续**，使用 `EAC = BAC / CPI`；若偏差由**一次性因素**导致、未来将回归计划，则用 `EAC = AC + (BAC − EV)`。公式选择的本质是对“偏差是否会持续”的管理判断。

**局限**

- **对数据质量高度依赖**：PV、EV、AC的准确性要求预算基线稳定、实际成本归集口径一致。弱基线或不一致的数据会使整套指标失去诊断价值。
- **进度指标的“货币化”失真**：SV和SPI以金额衡量进度，不直接回答“**落后了多少天**”。尤其在项目临近完工时，EV趋近于PV和BAC，即使实际工期严重延误，SV也会趋近于0、SPI趋近于1，掩盖真实的进度问题。挣得进度（Earned Schedule）方法以时间单位重新定义进度指标，正是对这一缺陷的修正。
- **不反映质量与关键路径**：传统EVM不直接捕捉可交付成果的质量水平，也不区分挣值来自关键路径活动还是非关键路径活动。非关键路径上超额完成的工作可能产生“进度良好”的假象，而关键路径的延误未必被及时暴露。

### 简要对照

|                | 净现值分析（NPV）        | 挣值管理（EVM）                |
| -------------- | ------------------------ | ------------------------------ |
| **决策问题**   | 项目是否值得启动         | 项目执行是否健康               |
| **时间视角**   | 事前，全生命周期         | 事中，截至报告时点             |
| **核心尺度**   | 折现后的**绝对货币价值** | 统一货币尺度下的**偏差与效率** |
| **主要输出**   | 采纳 / 放弃              | 成本与进度的诊断 + 完工预测    |
| **关键脆弱点** | 折现率的主观性           | 数据质量与进度指标的失真风险   |

两者共同构成了从**投资筛选**到**执行控制**的闭环：NPV在入口处判断一个项目是否应当进入，EVM在过程中判断已经进入的项目是否仍在轨道上。





在实际工作中，PV、EV、AC的计算远不止套用公式，其核心在于**将管理意图转化为可执行、可审计的数据采集规则**。PV源自**计划与预算的融合**，EV依赖于**客观的进度测量规则**，而AC则是**财务数据的严谨归集**。

### 📊 PV（计划价值）：源于“基线化的预算分布”

PV的计算公式虽简单（`PV = 计划工作量 × 预算单价`），但实际工作中，它是项目**成本基线（Cost Baseline）**在时间轴上的直接映射。

**数据来源与计算路径**

1. **基础是WBS与预算**：项目的工作分解结构（WBS）是根基，每个工作包都被分配了经批准的预算。项目总预算（BAC）由所有工作包的PV汇总而来。
2. **按进度计划分摊**：这是关键一步。需要将每个工作包的预算，根据其进度计划（如工期、里程碑）**分摊到各个报告期**。例如，一个预算为$16,521、工期17天的活动，其日均PV约为$972。若在检查点时计划已进行9天，则该活动的PV为$8,748。
3. **系统自动化汇总**：在专业工具（如Oracle Primavera P6）中，PV通常**并非手动计算**。系统会基于导入的进度和资源/成本数据，自动将预算随时间分布，得出任一数据日期（Data Date）的累计PV值。

**实操关键**：PV的本质是“**时间分段的预算**”。它反映的是“截至今日，按计划我们**本应**完成价值多少的工作”，而非“我们**计划花掉**多少钱”。因此，PV的准确性完全取决于**进度计划的质量和预算分摊的合理性**。

---

### 🎯 EV（挣值）：核心在于“进度测量规则”

EV的公式（`EV = 已完成工作量 × 预算单价`）看似与PV对称，但其难点和精髓在于 **“如何客观、一致地定义和测量‘已完成工作量’”**。在实际工作中，EV是通过**预设的进度测量规则（Technique）** 计算得出的。

**常见的EV测量规则与数据来源**

| 测量方法                             | 适用场景                                         | 如何获得EV（数据来源）                                       |
| :----------------------------------- | :----------------------------------------------- | :----------------------------------------------------------- |
| **固定公式法（0/100, 50/50等）**     | 短周期、子任务明确的工作包                       | 规则简单：工作未开始EV=0，开始后EV=50%（或100%），完成后EV=100%。**数据来源是任务的“开始/完成”状态标志**。 |
| **里程碑法（Milestone）**            | 有明确、可交付关键节点的活动                     | 为每个里程碑分配预算权重。**数据来源是里程碑的“已实现/未实现”状态**，每达成一个，就“挣得”对应比例的EV。 |
| **完成百分比法（Percent Complete）** | 工期较长、可量化物理进度的活动（如土方、代码行） | 由**成本账户经理（CAM）或技术负责人**基于客观物理测量（如完成立方数、代码行数）进行**主观评估**，或由系统根据**已投入工时**等指标自动计算POC，再乘以BAC得出EV。 |
| **加权里程碑/等效单元法**            | 复杂、包含多种子交付物的长周期活动               | 将工作包分解为多个带权重的“等效单元”（如设计图纸的张数、测试用例的个数）。**数据来源是已完成等效单元的统计**，EV为已完成单元权重之和占总权重的比例乘以工作包预算。 |

**实操关键**：EV的数据并非来自财务，而是来自**项目执行过程本身**（任务状态、里程碑达成、物理测量记录）。确保EV可信的核心是：**为每个工作包预先选定并固化一种测量规则，并在整个项目生命周期中一致地应用**。

---

### 💰 AC（实际成本）：源于“财务系统的严谨归集”

AC是三者中概念最直观的，但实操中最容易出现**口径不一致**和**数据滞后**的问题。它本质上是**已发生成本的财务汇总**，而非基于“工作量”的计算。

**AC的主要构成与数据来源**

| 成本类型               | 数据来源系统/方式                    | 统计要点                                                     |
| :--------------------- | :----------------------------------- | :----------------------------------------------------------- |
| **人工成本**           | **工时填报系统**                     | 这是研发/服务类项目AC的主要部分。需记录每位成员在**具体任务**上的实际投入时间，再乘以该成员的**实际费率**。关键在于**每日填报**，避免月底回忆导致失真。 |
| **材料/设备/外包成本** | **采购系统、合同台账、应付账款系统** | 基于**采购订单、收货单、供应商发票**进行归集。需注意将运输费、关税、安装费等**全部附带成本**纳入。 |
| **间接成本分摊**       | **财务系统（ERP）**                  | 办公租金、管理费用等，需按既定标准（如人力占比、工位数）分摊到项目。大型企业通常由ERP自动完成。 |
| **其他直接费用**       | **费用报销系统**                     | 差旅、会议等直接为项目发生的费用。                           |
